# 不使用 Codex，怎样用创造模式继续开发

普通使用者只需安装本插件，不需要创造模式。想修改插件或从零制作类似插件，可以直接在 DeepSeek Harness 桌面完成。

## 修改现有插件

1. 克隆本仓库，准备 README 中的依赖。
2. 在 Harness 选择「插件 → 添加插件」旁的创建入口，进入创造模式。
3. 将本仓库作为开发工作区，确认仍显示创造模式。
4. 发送清楚的改动要求，让它阅读当前官方文档、实现和测试。
5. 完成后退出当前测试进程，重新加载插件，再到另一个项目工作区用标准模式验收。

可以使用以下提示词，把方括号内容换成自己的需求：

```text
请在当前创造模式修改 paiwarp-dsh，实现：[具体需求]。
先读 README.md、docs/interface.md、CONTRIBUTING.md 和相关源码，
用创造模式提供的官方文档查询能力核实当前 Harness API，不猜接口。

保持插件通用：不绑定某个章节、项目、模型密钥、安装目录或 Codex。
桌面所见、Agent 所读、截图录像都来自同一个真实 PTY。
保留会话归属、输入序号防重复、权限检查、人工接管和取消清理。
只换图仍然只能改图片地址，保留其余字节，拒绝并发修改和不唯一匹配。

完成实现和必要的真实终端测试。分别报告已实现、已实测和未验证的部分，
不要把单元测试通过当成桌面验收，不把命令回显当作成功证据。
更新受影响文档和本地 npm pack，说明刷新方式；不要自行提交、推送或发布。
```

## 从零创建时说明什么

告诉创造模式要提供打开终端、读屏、输入、等待、截图、录屏、验证、只换图和关闭工具；右侧分终端/素材两页，人可以接管和交回。提供一份不依赖某个项目的任务说明，允许它选择合适实现，但要求参考官方接口。

验收至少包含独立安装目录与另一个工作区、真实交互与多行、普通 Python 项目、截图及可解码录像、关闭进程、桌面重启回看，以及仅换图的逐字节检查。示例只能作为材料，不成为核心的固定输入流程。

本项目原型和通用改造曾由 Harness 创造模式实现，外部助手协助操作桌面、审查和核对；运行与后续开发都不要求安装该助手。使用任意编码助手开发时，都应按当前源码和实际结果验证。

参考：[官方插件管理文档](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/client/ui-plugin-manager/README.zh.md)。该链接固定到本次验收版本，开发新版应再核实对应版本文档。
