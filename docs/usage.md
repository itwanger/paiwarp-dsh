# 使用指南

## 只给任务，还是先写 Case？

Case 就是一份写明输入、步骤和预期结果的测试案例。第一次可以直接给 Harness 教程路径；反复运行的任务，建议保存为工作区中的 CASE.md，参考 [模板](../examples/case-template.md)。

一个清楚的任务至少说明：在哪个项目运行、允许修改哪些目录、启动命令是什么、什么结果算通过、在哪几个阶段截图、什么时候退出。密码和密钥由本机配置提供，不写进命令、提示词或案例文件。

## Agent 和人如何操作同一终端

1. 在标准模式告诉 Harness 用 PaiWarp 打开终端并录制。
2. 它用 `paiwarp_open` 取得终端编号和输入序号，用 `paiwarp_input` 输入命令。
3. 每次输出后通过 `paiwarp_read` / `paiwarp_wait` 观察现场，决定下一步。没有输出或等待超时不算成功。
4. 你可以在面板接管；这时 Agent 的写入被拒绝，你可以输入或发送 Ctrl+C。
5. 交回后 Agent 可继续；对话若已进入等待回答状态，还需回复继续。
6. 完成后先停止录屏、再关闭终端，核对文件与状态，回看素材。

`paste` 粘贴多行时不补造最后一个回车；最后一行没有换行，程序可能还在等待 Enter。字母 `I` 属于普通文本，应使用 `mode: "text", text: "I"`，而不是声明成特殊按键。特殊按键支持范围见[接口](interface.md)。

## 验证什么才算跑通

- 输入回显：只能证明文字显示出来，不能证明命令成功。
- 文件：检查内容、数量、结构，必要时解析 JSON 或比较摘要。
- 命令退出：使用程序返回后的真实状态，不把后一条检查命令的退出码冒充前一条。
- Agent 业务行为：它声称“保存成功”，还要看实际数据或工具记录。
- 录像：停止后检查可解码，并在桌面播放器试播。

`paiwarp_verify` 的检查必须由调用者提供；插件不会自动理解所有业务正确性。多次调用会更新 `checks.json` 的最近检查结果，报告应保留各步骤依据，不能只展示最后一个绿色状态。

## 只换图片，不动文本

先保留原文，并明确目标图片位置。`paiwarp_replace_images` 默认只生成方案，返回匹配数量和原文件 SHA-256；已有用户授权且方案确定后，带回摘要应用。期间文件改变、匹配不唯一或格式不支持，就报告原因。

支持独占一行的 `![alt](地址)`。新相对地址写成 `./images/a.png` 或 `../images/a.png`。正文、alt（图片替代文字）、代码块、普通链接、空白、换行应逐字节保留。它不是 Markdown 全文重写工具。

正式教程先使用演示副本试换；如果测试失败而正文仍描述成功，不应直接发布这份换图副本。站点副本需单独指定和验证；插件不自动查找或上传图床。

## 多个项目和多个终端

插件安装位置不决定工作目录，当前 Harness 工作区才决定。切换项目后另开会话；同一会话里多个终端要明确 `terminal`，不要只依赖“最近一个”。终端编号和输入序号分别处理会话归属与防重复，关闭后的记录只能查看。
