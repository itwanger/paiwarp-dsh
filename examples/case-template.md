# CASE：填写你的项目名称

## 目标

这次验证什么：例如程序能完成一轮真实交互，生成预期文件，并正确处理错误输入。

## 准备

- 当前工作区：待测项目目录。
- 依赖及版本：填写本机运行时、构建工具。
- 构建命令：填写实际命令，没有就注明。
- 启动命令：填写实际命令，不使用猜测的包名或路径。
- 配置：说明配置文件或环境变量名称，不填写密钥。
- 修改边界：明确只可写入哪些临时目录，哪些文件不允许修改。

## 操作与预期

1. 读取项目说明，确认环境齐备。
2. 用 PaiWarp 打开真实 Bash 并开始录像，构建后检查实际退出码。
3. 启动程序，等待实际就绪信号；截图“启动”。
4. 输入一条正常任务，核对文件或输出的具体预期；截图“结果”。
5. 输入一条错误任务，核对错误内容与文件是否保持预期；截图“错误”。
6. 按需重启程序，核对持久化结果。
7. 正常退出，立即记录实际退出状态。

请把上述占位描述改成项目真实的命令、输入与预期，执行前不要猜测缺失信息。

## 通过条件

- 写明应产生的文件、准确内容或可计算断言。
- 命令回显和 Agent 自述不能单独证明通过。
- 缺依赖、权限或证据时标受阻/未验证；失败保留原始现场，不重跑挑结果。

## 素材与收尾

保存关键截图、完整可解码录像、输入输出、逐项报告。最后停止录屏并关闭本次进程，不关闭其他任务。

默认不改教程。如另行授权换图，先在副本中生成方案，明确原地址与截图对应关系，核对除图片地址外所有字节一致。
