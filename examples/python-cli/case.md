# CASE：用 PaiWarp 测试 Python 待办程序

## 目标与准备

这是普通命令行程序，不依赖 PaiCLI、Java 或模型密钥；外层 Harness 仍使用它自己的模型服务。只需要 Python 3.9+ 标准库。

使用一个新的独立工作区，里面放 `todo.py` 和本文件（可改名 CASE.md）。开始前检查 `todos.json` 不存在；存在则报告并另选目录，不覆盖旧数据。

请用 PaiWarp 通用工具逐步驱动真实终端，不用整段自动运行脚本代替交互。允许的文件修改仅限当前示例工作区。验证程序可以读取 JSON，但不能代替待办程序添加和完成任务。

## 操作

1. 用 `paiwarp_open` 打开 `/bin/bash`，设置 `record: true`。
2. 输入 `python3 todo.py todos.json`，等 `todo>` 提示符。
3. 输入 `list`，确认显示 `（空）`，截图 `01-empty`。
4. 多行粘贴 `add 买咖啡` 和 `add review pull request`。如最后一行尚未提交，观察后补发 Enter。
5. 输入 `done 1`、`list`，确认第一条 `[x]`、第二条 `[ ]`，截图 `02-tasks`。
6. 读取并记录 `todos.json` 的 SHA-256；输入 `done 99`，确认报“没有这个编号”，文件摘要未变；截图 `03-error`。
7. 输入 `quit`，等回到 Bash，立刻记录这次 Python 的实际退出码。
8. 重新启动 `python3 todo.py todos.json`，输入 `list`，确认两条记录及完成状态仍在，截图 `04-persistence`。
9. 再次 `quit`，立刻记录退出码。

## 核对

精确解析 `todos.json`，内容必须等于：

```json
[
  {"text": "买咖啡", "done": true},
  {"text": "review pull request", "done": false}
]
```

确认恰好两个对象、各字段值正确。还要核对错误输入前后文件没有变化、两次 Python 退出码都是 0。不要仅检查是否出现“成功”，不要拿后续验证命令的退出码冒充被测程序退出码。

用 `paiwarp_verify` 保存文件内容、摘要和退出状态检查；报告额外保留重启与错误输入的证据。至少保存三张截图及完整录像，失败项照实保留。

正常停止录屏，检查视频可解码，再关闭本次终端及子进程。写 REPORT.md，列出真实结果、文件/退出状态证据和截图视频位置。
